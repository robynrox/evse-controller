DP backtest

This is the technical view of Learning mode, which uses dynamic programming (DP). The first preview plan of each day is replayed against the measured grid load and frozen prices. The DP cost replaces the actual EVSE action, so it is comparable with the heuristic's net cost over the same slots. Positive delta means the DP plan would have been cheaper. This is a first-order sanity check: it does not re-solve battery constraints or supplier rewards. The solver version records which planner generation produced each day.

Re-solve with the current solver

Re-runs recorded plans using the current planner parameters and writes the results to a new job directory. First plan is fast; rolling re-solves at every slot and is much slower. The recorded runs are never modified, so jobs can be compared by solver version and by date.

What do these settings mean?
Scope
First plan re-solves only the first recorded plan of each day, then prices it against the measured day. It is fast and is the right choice for a first look. Rolling re-solves at every half-hour slot using the latest recorded plan available at that time. It is much slower but closer to how the planner would behave in a live closed loop.
Baseline
The recorded plan the re-solved plan is compared against. First plan uses the day's first recorded plan. Plan in force stitches together the latest recorded action for each slot, which is what the controller was actually following at the time. The baseline always keeps the recorded load input.
Rolling SoC
Only used by the rolling scope. Simulated carries the solver's own SoC path forward from slot to slot. Recorded estimate uses the SoC estimate recorded at each slot instead, which isolates policy decisions from simulated SoC drift.
Load input
Recorded load uses the load profile recorded with the original plan. Component forecast replaces the re-solved plan's load with the weather-driven forecast: baseload(slot) + heat pump(temperature) − solar(irradiance). The baseline still uses recorded load, so the A/B result shows whether the better forecast changes decisions. Days with missing forecast weather are skipped and listed in the result.
